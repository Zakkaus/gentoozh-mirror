关于这个 Live ISO

Gentoo 中文社区每周构建的 KDE Plasma 6 桌面 Live ISO。中文环境、输入法、字体与显卡驱动都已配好,可直接试用,也可安装到硬盘。

启动菜单

GRUB 顶部三档语言:简体中文 / 正體中文(臺灣)/ English。选定后桌面、Firefox 与输入法一并跟随。下方四项各自也含三种语言:

  • 闭源 NVIDIA 驱动:新卡需要硬件加速时用,须先关闭 Secure Boot(见下)。
  • 安全显卡模式:nomodeset,点不亮的显卡用它进桌面。
  • 拷贝到内存:整盘载入内存后运行,U 盘可拔,速度更快。
  • 从本地硬盘启动:误插 U 盘时用。

中文输入法

默认朙月拼音(简体)。右键托盘的输入法图标,选「方案」即可启用或切换注音、五笔86、仓颉、粤拼等,新方案首次使用需在列表里勾选。

  • Ctrl + ` 在已启用的方案之间切换。
  • Ctrl + 空格 开关输入法。

显卡驱动

默认使用开源 nouveau,即插即用。RTX 20/30/40/50 需要硬件加速时,在启动菜单选「闭源 NVIDIA 驱动」。

闭源驱动模块未签名,须先在 BIOS 关闭 Secure Boot,否则内核拒绝加载,表现为黑屏或卡住。与 Windows 双系统且想保留 Secure Boot 的,可在装机期间临时关闭,或装好后给模块签名并录入 MOK 密钥。显卡仍点不亮时,用「安全显卡模式」。

安装到硬盘

想完整了解系统,建议照 Gentoo 官方手册一步步安装。桌面也提供图形安装器:双击「安装系统」启动 Calamares,界面语言跟随 live 中所选。安装完成后会自动清除 live 专用配置(开机自动登录等),并按所选显卡为新系统配好驱动。

文件系统与加密

分区页可选根文件系统,默认 btrfs,另有 xfs、ext4 与 ZFS。

  • ZFS 根:选 ZFS 并勾选加密,即使用 ZFS 原生加密(aes-256-gcm),由 ZFSBootMenu 引导。GRUB 读不了带新特性或原生加密的 ZFS 池,因此 ZFS 根改用 ZBM。开机需输两次密码(ZBM 一次、系统 initramfs 一次),属正常现象。
  • LUKS 全盘加密:xfs / ext4 / btrfs 在分区时勾选 LUKS,由 GRUB 引导,通常只需输一次密码。

硬件要求

x86-64AVX22013 年之后的处理器

镜像按 x86-64-v3 编译,必须有 AVX2,更早的 CPU 无法启动。

虚拟机:VirtualBox 通常透传不了 AVX2(Hyper-V/WHP 后端没有,原生 VT-x 后端也常没有),镜像多半起不来。请用 KVM(-cpu host)、原生 Hyper-V 或 VMware。进入系统后可用 grep -o avx2 /proc/cpuinfo 实测。

登录信息与校验和见下载页。安装完成后,编译参数 CPU_FLAGS_X86 会在首次开机按本机 CPU 自动生成。

About this Live ISO

A KDE Plasma 6 desktop Live ISO built weekly by the Gentoo-zh Community. The Chinese environment, input methods, fonts and graphics drivers are already set up. Run it live or install it to disk.

Boot menu

The top of the GRUB menu offers three languages: Simplified Chinese / Traditional Chinese (Taiwan) / English. The desktop, Firefox and the input method all follow your choice. The four entries below are each available in all three languages:

  • Proprietary NVIDIA driver: for hardware acceleration on newer cards. Secure Boot must be disabled first (see below).
  • Safe graphics mode: nomodeset, for cards that will not light up otherwise.
  • Copy to RAM: loads the whole image into memory, so the USB stick can be removed and things run faster.
  • Boot from local disk: for when the USB stick was left plugged in.

Chinese input

The default is Pinyin (Simplified). Right-click the input method tray icon and open "Schema" to enable or switch to Zhuyin, Wubi 86, Cangjie, Cantonese and others. A new schema has to be ticked in the list before first use.

  • Ctrl + ` cycles through the enabled schemas.
  • Ctrl + Space toggles the input method.

Graphics drivers

The open-source nouveau driver is used by default and works out of the box. For hardware acceleration on RTX 20/30/40/50 cards, pick the proprietary NVIDIA entry in the boot menu.

The proprietary module is unsigned, so Secure Boot must be disabled in the BIOS first, otherwise the kernel refuses to load it and you get a black screen or a hang. If you dual-boot Windows and want to keep Secure Boot, turn it off for the installation and back on afterwards, or sign the module and enroll a MOK key once installed. If the card still will not light up, use safe graphics mode.

Installing to disk

To understand the system properly, follow the Gentoo Handbook step by step. The desktop also ships a graphical installer: double-click "Install System" to launch Calamares, which follows the language you picked in the live session. When it finishes it clears the live-only settings (autologin and so on) and sets up the graphics driver on the installed system to match your choice.

Filesystem and encryption

The root filesystem is chosen on the partitioning page. The default is btrfs; xfs, ext4 and ZFS are also available.

  • ZFS root: choose ZFS and tick Encrypt to use ZFS native encryption (aes-256-gcm), booted by ZFSBootMenu. GRUB cannot read ZFS pools that use newer features or native encryption, so a ZFS root uses ZBM instead. You enter the passphrase twice at boot (once at ZBM, once in the system initramfs), which is expected.
  • LUKS full-disk encryption: tick LUKS while partitioning xfs / ext4 / btrfs. It boots via GRUB and usually asks for the passphrase once.

Hardware requirements

x86-64AVX2CPU from 2013 or later

The image is built for x86-64-v3 and requires AVX2. Older CPUs cannot boot it.

Virtual machines: VirtualBox usually cannot pass AVX2 through (the Hyper-V/WHP backend never does, and the native VT-x backend often does not either), so the image will not boot. Use KVM (-cpu host), native Hyper-V or VMware. Inside the guest, grep -o avx2 /proc/cpuinfo tells you for certain.

Login details and checksums are on the download page. After installation, the CPU_FLAGS_X86 compile setting is generated on first boot from your own CPU.
